## 1. 执行摘要

本次审计对 MoeRNG（自托管二次元图床，PHP 单体应用）仓库源码进行了全量静态深度审查，覆盖 Core 框架、全部控制器、Models/schema、8 个存储驱动、前端视图与 JS、第三方 SDK 供应链、发布链脚本、部署配置与文档合规。审计为纯静态审查 + 本地 Node 语义复刻，未连接真实 PHP 运行时 / MySQL / 对象存储（本机无 PHP CLI 与部署实例），凡依赖真实运行态的结论均在第 7 章列为「无法验证项」。

**总体判定：** 代码主干在 SQL 注入、CSRF、主图上传 magic bytes、删除链、签名下载 URL、凭据静态加密等基线上质量良好（多处已逐项验证通过）；但存在 **1 个可直接利用的垂直越权高危、1 个会话硬化被架空的会话高危、1 个云对象孤儿对象资金风险、1 个又拍云防盗链签名实现全错、1 个 API Key 明文落库**，叠加发布链无 CI 门禁、SDK 钉在 dev 分支等工程债，**当前不建议在此状态下直接对外 GA**。

### 1.2 最紧急的 5 个问题（必须立即处理）

1. **MR-02 · editor 角色零服务端强制（垂直越权）**：`schema.sql:33` 定义了 `role ENUM('admin','editor')`，视图也在分发 editor 账号，但 `AuthMiddleware.php:44-58` 只校验「登录 + active」、全仓零处 `requireAdmin`/role 守卫，`UserController.php:30` 甚至允许任意登录用户把新账号置为 admin。**任何 editor 账号等同 admin**，可建管理员、删图、改存储凭据、读明文 SecretKey。
2. **MR-01 · 会话 Cookie 硬化被 CspNonce 提前 `session_start()` 架空**：`Application.php:57` 先发 CSP → `CspNonce.php:26` 裸 `session_start()` 先于 `Session.php:23-37` 的硬化块执行，此后 `session_status()===ACTIVE`，`Session::start()` 的 HttpOnly / SameSite=Lax / Secure 整段被门禁跳过——开发者写好的会话硬化在正常 web 请求上是死代码。
3. **MR-05 · 云端孤儿对象无回收（资金风险）**：`ImageController.php:887` 原图先上传云端、`:937` catch 只删本地临时文件并标 failed，已上云对象无 LIST、无回收；另一条触发路径是 `:1956` `queueClear()` 裸 `DELETE FROM images` 绕过 `Image::delete()`。失败路径与成功路径代码不对称，孤儿对象按 bucket 流量计费且站内无法发现。
4. **MR-04 · 又拍云防盗链签名与官方规范全维度不符**：`UpyunSdkDriver.php:118-124` 用 `_up_t={etime}_{md5(operator:password:expires)}`，而官方规范为 `_upt={md5(key&etime&URI)中间8位}{etime}`——参数名、拼接格式、签名串（URI 是否参与）、分隔符、密钥来源五项全错。结果二选一：开防盗链则全线 403，不开则裸 URL 永久公开。
5. **MR-03 · API Key 明文落库**：`ApiKey.php:21-24` 按原始 key 等值查询、`schema.sql:29` `key VARCHAR(128) UNIQUE` 为明文列；同库内 remember_token 已正确 SHA-256 哈希，两种令牌两种保护级别。DB 泄露即全部在途 API Key 直接可用。

### 1.3 上线/发布/投资建议

- **是否对外 GA**：当前为 beta 迭代节奏，**不建议在此状态下直接对外 GA**。建议先完成全部 P1 修复（预计 3–5 人日）再推进 GA。
- **继续投资建议：是**。代码基线上乘（注入/CSRF/主删除链/签名机制均已验证达标），问题集中在「角色强制、密钥生命周期、并发原子性、发布链门禁」四类可工程化收敛的系统性债务；但**必须先补 CI 门禁与发布链可复现性**（MR-08/06/07），否则后续 beta 迭代仍靠人工纪律兜底。

### MR-01 · 会话 Cookie 硬化被 CspNonce 提前 session_start() 架空

- **ID**：MR-01
- **严重性**：High
- **置信度**：高（调用链逐行回溯；实际失效程度取决于目标机 php.ini 默认值，待部署环境验证）
- **类别**：会话安全
- **修复优先级**：P1
- **位置**：`src/app/Core/Application.php:57`（bootstrap 首次发 CSP）、`:136` → `CspNonce::token()`；`src/app/Core/CspNonce.php:23-29`；`src/app/Core/Session.php:15-37`
- **证据**：
  - `Application.php:136-137`：`sendSecurityHeaders` 内 `$nonce = \App\Core\CspNonce::token();`
  - `CspNonce.php:23-29`：
    ```php
    public static function generate(): void {
        if (session_status() !== PHP_SESSION_ACTIVE) {
            session_start();              // ← 裸调用，无任何 cookie 参数设置
        }
        $_SESSION[self::SESSION_KEY] = bin2hex(random_bytes(32));
    }
    ```
  - `Session.php:15-37`：所有硬化逻辑都在同一条件分支内：
    ```php
    if (session_status() === PHP_SESSION_NONE) {
        session_set_cookie_params([... 'secure'=>$isSecure, 'httponly'=>true, 'samesite'=>'Lax']);
        @ini_set('session.use_strict_mode', '1');
        @ini_set('session.cookie_httponly', '1');
        @ini_set('session.cookie_samesite', 'Lax');
        session_start();
    }
    ```
  - 全 src 裸 `session_start()` 调用点：`CspNonce.php:26 / :45 / :92`，`Session.php:37`（唯一带硬化的，但被门禁）。
  - 因果链：任意请求（前台首页也发 CSP）→ `sendSecurityHeaders(false)` → `CspNonce::token()` → 此时无会话 → `CspNonce::generate()` 裸 `session_start()` 并发出 PHPSESSID Set-Cookie；此后 `session_status()===PHP_SESSION_ACTIVE`，`Session::start()` 硬化块整体跳过。登录后 `AuthController.php:97` 的 `session_regenerate_id(true)` 发生在更后面，生效 cookie 参数仍是 php.ini 默认值。
- **影响**：在 php.ini 默认未硬化的主机上，PHPSESSID 不带 HttpOnly（XSS 可窃取）、不带 SameSite=Lax、HTTPS 下也不带 Secure。`Session.php:16-20` 注释明确声称的「harden the session cookie — HttpOnly + SameSite=Lax always, Secure whenever TLS」在正常 web 请求路径上**不生效**，硬化代码事实上成为死代码。残留缓冲：登录仍轮换 ID、管理端有独立 CSRF token，非直接权限绕过，但 cookie 属性缺失抬高所有其他防线成本。
- **触发条件·利用路径**：① 新受害者首次访问站点任意页面；② 服务端经 CspNonce 发出未硬化 PHPSESSID；③ 若存在任一反射/存储 XSS，`document.cookie` 可读走会话；或纯 HTTP 降级/公共 WiFi 明文嗅走。
- **根因**：会话初始化顺序倒置——CSP nonce 生成器（横切关注点）先于会话硬化启动会话，且其内部用裸 `session_start()` 而非统一的 `Session::start()`。
- **修复建议**：`CspNonce::generate()/get()/requireNonce()` 一律改为 `Session::start()`（或在 `Application::bootstrap()` 最开头先 `Session::start()`），杜绝裸 `session_start()`；或把 `sendSecurityHeaders()` 推迟到会话硬化之后。补回归测试：干净 php.ini 下发任意请求，断言 `Set-Cookie: PHPSESSID=...; HttpOnly; SameSite=Lax`。
- **验证方法**：已通读 bootstrap 全文确认 line 57 前无任何 `Session::start()`；中间件链顺序脚本确认无其他会话入口；登录前 `Controller::validateCsrf → Session::verifyCsrf → Session::start()` 时会话已被 CspNonce 启动、门禁跳过。待部署环境：`curl -v` 发任意请求观察 Set-Cookie 属性。
- **参考**：`AuthController.php:94-98`（regenerate_id 注释）。

### MR-02 · editor 角色零服务端强制（垂直越权，editor≡admin）

- **ID**：MR-02
- **严重性**：High
- **置信度**：高

- **修复优先级**：P1

- **证据**：

- **验证方法**：grep 全控制器应出现 role 守卫；用 editor 会话逐一访问 admin 动作应 403。已逐 action 核对路由归属。
- **参考**：CWE-862（Missing Authorization）/ CWE-269。

### MR-03 · API Key 明文落库（对照 remember_token 已哈希）

- **ID**：MR-03
- **严重性**：High
- **置信度**：高
- **类别**：密钥管理
- **修复优先级**：P1
- **位置**：`src/app/Models/ApiKey.php:21-24`；`src/schema.sql:29`；`src/app/Controllers/Admin/ApiKeyController.php:46-53`
- **证据**：
  - `schema.sql:29`：`` `key` VARCHAR(128) NOT NULL UNIQUE `` —— 明文列。
  - `ApiKey.php:21-24`：`public static function findByKey(string $key) { return self::firstWhere('key', $key); }` —— 按**原始密钥**等值查询，即 DB 存的就是明文本身。
  - 开发者自认注释（`ApiKeyController.php:47-49`）：Key 同时完整存于 DB，一次性展示只是 UX 便利。
  - 对照组：`User.php:53-54` remember_token 已正确处理为 `hash('sha256', $raw)` 后入库、按哈希反查。同一代码库内两种令牌两种保护级别。
- **影响**：数据库泄露（SQL 注入、备份文件拖库、运维直读）即等于全部在途 API Key 直接可用，无需破解；Key 一经泄漏无法「轮换哈希」，只能逐枚重发。
- **触发条件·利用路径**：任何能读到 api_keys 表行的人（DBA、备份文件拿到者、SQL 注入落库者）直接拿 `key` 列作为 `x-api-key` 调用公开 API。
- **根因**：生成时图直查便利，未采用「存哈希 + 前缀/后八掩码对照」模式；create() 一次性明文展示后未做哈希落库。
- **修复建议**：库内存 `key_hash CHAR(64)`（sha256）+ `key_prefix VARCHAR(24)` 供展示；findByKey 改为 `WHERE key_hash = SHA2(?,256)`；UNIQUE 建在 key_hash 上；存量明文行给一次性强制重发迁移。
- **验证方法**：已读 ApiKey.php 全文与 present()（对外仅截前 16 字符展示，脱敏正确但落库仍是明文）；中间件每请求 findByKey 直查已互证。修复后验证：DB 查询无明文 key。
- **参考**：既有历史修复只处理了「列表不回显全量」，未修落库形态。

### MR-04 · 又拍云防盗链签名与官方规范不符（参数名/签名串/密钥源全错）

- **ID**：MR-04
- **严重性**：High
- **置信度**：高（算法逐字段对照官方文档；实际部署表现依赖控制台开关）
- **类别**：存储安全
- **修复优先级**：P1
- **位置**：`src/app/Storage/UpyunSdkDriver.php:116-124`
- **证据**：
  ```php
  // UpyunSdkDriver.php:118-124
  $expires = time() + $this->signedTtl;
  $sign = md5("{$this->operator}:{$this->password}:{$expires}");
  $host = $this->sourceDomain !== '' ? $this->sourceDomain : $this->service . '.b0.upaiyun.com';
  ```

  官方规范（docs.upyun.com/cdn/advanced/）：`_upt = MD5(密钥 & etime & URI){中间8位} + etime`，PHP 示例 `$sign = substr(md5($key.'&'.$etime.'&'.$path), 12, 8) . $etime;`，URL 形如 `<bucket>/dir/pic.jpg?_upt=abcdefgh1370000600`。
  逐字段对照：参数名官方 `_upt` vs 本实现 `_up_t`（❌）；格式官方 `{md5中段8位}{etime}` 直连 vs 本实现 `{etime}_{完整32位md5}`（❌）；签名串官方 `md5(密钥&etime&URI)`、URI 参与 vs 本实现 `md5(operator:password:expires)`、**无 URI**（❌ 路径不绑定）；分隔符官方 `&` vs `:`（❌）；密钥来源官方控制台独立「Token 防盗链密钥」 vs 本实现复用操作员 API 密码（❌ 设计上无配置项承载独立密钥）。
- **影响**：二选一双输：① 空间控制台**开启** Token 防盗链 → 所有 `?_up_t=...` 链接校验必败，图片全线 403（可用性事故）；② **未开启**（站点「能用」的更可能情形）→ CDN 节点忽略该参数，裸 URL 长期永久公开——注释声称的「私有空间短时链接」是假象，链接一旦被捕获，过期后仍可直读。另违反项目自述「全部官方 SDK、零自研签名」原则。
- **触发条件·利用路径**：使用 upyun 驱动的实例，图片 URL 出现在任意页面 → 被保存/分享的链接永久有效（情形 2）。
- **根因**：自研签名未对照厂商文档；providerFieldDefs 根本没有「防盗链密钥」字段，设计上无法填入正确密钥。
- **修复建议**：url() 按官方 `substr(md5($key.'&'.$etime.'&'.$path),12,8).$etime` 重写；StorageProfile config 增加独立防盗链密钥字段并纳入密封；doctor.php 增加「又拍云防盗链模式与配置一致性」检查。
- **验证方法**：真实空间开/关 Token 防盗链各请求一次生成 URL，观察 403 vs 200；与官方示例逐字节比对（所需环境：真实又拍云空间凭据）。

### MR-09 · 限流计数 TOCTOU + rate_limits 表缺唯一键

- **ID**：MR-09
- **严重性**：Medium
- **置信度**：高（DDL 与代码路径明确；真实 MySQL 并发行为待验证）
- **类别**：并发/限流

- **证据**：
  - DDL（`:111-123`）：`rate_limits` 表 `identifier VARCHAR(64)` + `window_key VARCHAR(64)`，索引为 `INDEX idx_identifier_window (identifier, window_key)` —— **普通索引，非 UNIQUE**（schema.sql:120 同）。

  - 判限（`:68`）：`if ($currentCount >= $maxRequests)`。
  - 写（`:83-91`）：有行走 UPDATE、无行走 INSERT —— **SELECT 与写之间无事务/无唯一约束兜底**。
- **影响**：同一 (identifier, window_key) 窗口首瞬间并发 N 个请求：全部 SELECT 到 0 行 → 全部 INSERT → 产生 N 行同键重复计数行；后续 fetch() 永远只读其中一行 → 计数长期停在低位，**限流器对该键形同失效**。即使无重复行，「读-判-写」窗口内并发都在计数自增前放行，实际放行数 > maxRequests。（默认 `api_rate_limit_enabled=0`，仅运维显式开启后受影响；一旦开启可被并发打穿。）
- **触发条件·利用路径**：运维开启限流后，攻击者在窗口第 0 秒并发发 N 个相同 API 请求（N >> maxRequests）→ 首批全部通过，后续持续放行。
- **根因**：计数表缺业务唯一键；读写分离无事务/无原子 upsert（对照 `Stats.php:23-26` 已正确使用 ON DUPLICATE KEY UPDATE 模式）。
- **修复建议**：DDL 改 `UNIQUE KEY uq_ident_window (identifier, window_key)`；计数改为单条原子 upsert `INSERT ... ON DUPLICATE KEY UPDATE request_count=request_count+1`，再 SELECT 判定；expires_at 清理保留。
- **验证方法**：node 复刻（第 4 段）构造两条同 (id,w) 行模拟 fetch() 取一条 → count=1，确认「limit=60 时永远 < 60 → 限流失效」。真实 MySQL 并发（未验证）：测试库 + `wrk`/`ab` 并发 100 打同一随机端点，观察重复行与 429 是否触发。
- **参考**：无。

## 5. 系统性根因与模式

跨分片归纳出 7 组反复出现的工程模式，每条映射对应 MR：

a) **角色/能力定义与代码强制脱节**：schema 定义了 editor 角色（MR-02）与 images.status 死值 hidden/deleted（MR-57），但代码零强制/零消费——「定义了却未落地」模式。字段存在、UI 暴露、下游无授权决策。

b) **密钥生命周期缺乏端到端统一策略**：明文落库（MR-03）、明文回显（MR-12/23）、不可用时降级明文（MR-11）、漏密封裸 key（MR-36）、密钥文件权限不一致（MR-28/50）、无轮换备份（MR-49）、PAT 处理无纪律（MR-26）——密钥面七处独立决策，无单一策略，加密的静态承诺在传输层/展示层/降级路径反复漏水。

c) **并发防护只做局部**：限流 TOCTOU（MR-09/10）、队列复位与条件认领互相抵消（MR-15）、backfill 无认领（MR-37）、随机取图两步法（MR-33/34）——「防并发」普遍未覆盖读-改-写全程，单点原子了但相邻步骤没跟上。

d) **失败路径资源清理缺失**：孤儿对象（MR-05）、预签名失败无日志（MR-42）、downloadUrl 无大小闸（MR-43）——失败路径与成功路径代码不对称，资源回收/可观测只在 happy path 写。

e) **审计留痕系统性稀疏**（MR-38、MR-54）：高危写操作无审计、审计写入失败静默——审计策略缺顶层设计，埋点是补丁式而非约定式。

f) **发布链工程债**（MR-06/07/08/25/27/47/48）：无 CI、脚本不入库、移动分支依赖、全量 git add、立即发布——发布可靠性依赖人工纪律，无第二证明渠道。

g) **文档/注释漂移**（MR-51/60/72 及 MR-09/11 类注释自认）：注释承诺与实现脱节、README 与实际部署脱节、版本快照滞后；且 E-01 推翻了既有审计「前端无用户数据进 innerHTML」结论——审计与文档均未成为持续流程，历史结论会随代码演化失效。

### 8.3 术语表

- **MOERNG_ROOT**：应用安装根目录（src/ 的上一级）。
- **处理队列 / process_status**：图片处理状态机字段，取值 pending→processing→done/failed；failed→pending（requeue）。
- **processing_state / thumb_meta**：缩略图补全子状态（pending/ok/partial/failed/skipped），deriveThumbMeta 为唯一推导来源。
- **storage profile**：存储实例配置（驱动类型 + 加密凭据 + endpoint/bucket/cdn/TTL）。
- **缩略图链 THUMB_SIZES**：sm/md/lg 三档，生成/读取同源常量。
- **CredentialCipher / enc:v1: 前缀**：AES-256-GCM 静态加密器，密文带此前缀标识已密封，重复 save 幂等跳过。
- **SignedUrl / 时间窗口对齐**：本地文件 HMAC 签名下载机制；expires 按 60s 窗口取整以使窗口内 URL 可缓存。
- **伪静态**：nginx/Apache URL 重写规则段。
- **宝塔（BT）**：常见服务器面板，部署文档面向其 nginx 站点配置。
- **token bucket**：登录限流的令牌桶/固定窗口语义。
- **fail-closed / fail-open**：失败时拒绝 vs 失败时放行/降级。
- **TOCTOU**：Time-Of-Check to Time-Of-Use，检查与使用之间的竞态窗口。
- **孤儿对象**：DB 已无引用但仍残留在对象存储中的文件。
- **soft-delete**：软删除（标记位而非物理删除）；本项目 images 实际为硬删除（见 MR-57）。
- **fillable**：模型允许 mass-assignment 的字段白名单。

### 8.5 严重性定义

- **Critical**：可直接远程未授权获取系统控制权/全量数据，或无需交互即可大规模利用。本项目本次审计为 0。
