## 1. 问题清单

### 1.1 阻断（5 项，全部已修）

#### A-01 `schema.sql` 注释含分号 → 全新安装必然失败 🔴
- **模块**：安装向导 / 数据库
- **位置**：`src/schema.sql:30`、`:129`、`src/app/Controllers/InstallController.php:376`
- **根因**：安装器用 `explode(';')` 切分 SQL，而两行注释内含分号：
  - `-- kept for lookup (same pattern as users.remember_token); key_prefix is`
  - `-- on ON DUPLICATE KEY; without a true UNIQUE constraint concurrent requests`
- **影响**：切分后产生 9 个片段，其中 4 个是语法错误。`api_keys` 与 `rate_limits` **建表语句被截断**，第 3 个语句即抛 `PDOException`，被 `complete()` 的 `catch (\Throwable)` 吞掉 → 用户看到「安装失败」退回 step1，**两张表根本没建上**。已装站点不受影响（表已存在）。
- **修复**：切分前用 `preg_replace('/^[ \t]*(?:--|#).*$/m', '', $sql)` 剥离整行注释。
- **验证**：实测切分从 9 片段（4 坏）变为 7 片段（0 坏），全部以合法 SQL 关键字开头。

#### A-02 `batchCategorize` 调用 protected 方法 → 端点恒 500 🔴
- **模块**：业务逻辑 / 图片管理
- **位置**：`src/app/Controllers/Admin/ImageController.php:2645`
- **根因**：`Model::update()` 是 `protected function update(): bool`（无参），`Image` 未覆写。原代码 `$image->update(['category_id' => ...])` 双重错误——外部调用 protected + 多传一参，必抛 `Error` / `ArgumentCountError`。
- **影响**：`POST /admin/images/batch-categorize` **每次调用都 500**，该功能自上线起从未成功执行过。同文件单张 `update()` 用的是正确写法，说明批量路径写错了。
- **修复**：改为 `$image->category_id = ...; if ($image->save())`。**1 行。**

#### A-03 `.htaccess` 根级 FilesMatch → Apache 全站 403 🔴
- **模块**：部署配置 / 安全
- **位置**：`src/.htaccess:22-29`
- **根因**：MR-14 把无效的 `<Directory>` 块（该指令在 .htaccess 上下文非法，只在 server/vhost 中有效，故原写法是静默空转）改写为 `.htaccess` **根级** `<FilesMatch "\.php$"> Require all denied`。但 `<FilesMatch>` 对当前目录**及所有子目录**递归生效，而本文件所在的 `src/` 正是前端控制器目录。
- **影响**：`index.php` / `api.php` / `admin.php` / `install.php` / `doctor.php` / `bootstrap.php` **全部被拒 → Apache 部署直接全站瘫痪**。线上是 Nginx 故生产未受影响。且 `src/public/uploads/.htaccess` 已有正确防护，此改动**既多余又有害**。现有 CI 三道门禁都不检查 `.htaccess`，完全不可见。
- **修复**：回滚该块（保留说明为何不能在根级写），防护交由上传目录自带的 `.htaccess`。
- **补充**：`.htaccess:15` 的拒绝清单**漏了 `storage/`**（`nginx.conf.example:49` 有）→ doc-root=项目根的 Apache 部署可直接下载 `storage/uploads/**`，**整个图库绕过 `/files` 签名**。已补齐。

#### A-04 限流可被任意 `X-API-Key` 头完全绕过 🔴
- **模块**：安全 / 限流
- **位置**：`src/app/Middleware/RateLimitMiddleware.php:103`
- **根因**：`getIdentifier()` 只要 `X-API-Key` 头**非空**就用它的 md5 当桶标识，**不校验该 key 是否真实存在且启用**。
- **影响**：开启限流后，攻击者每次带一个随机头即可获得全新 `rate_limits` 行（UNIQUE 约束在 `(identifier, window_key)`），计数从 1 重新开始 → **IP 维度限流形同虚设**，且每请求新增一行造成表无界膨胀。
- **修复**：只对 `ApiKey::findByKey()` 验证通过且 `status='active'` 的 key 按 key 计桶，否则回退 IP。**5 行。**

#### A-05 `rate_limits` 唯一键在存量库永不建立 → 限流彻底失效 🔴
- **模块**：数据库 / 限流
- **位置**：`src/app/Core/Application.php`（迁移列表）、`RateLimitMiddleware.php:136`
- **根因**：`UNIQUE uq_ident_window` 只出现在 `schema.sql` 与 `CREATE TABLE IF NOT EXISTS`——两者**只对新建表生效**。而 `Application::runStorageMigration()` 的自迁移列表**不含 rate_limits**，旧表已存在的站点 `ensureRateLimitTable()` 探测成功即 `return`，永不补索引。
- **影响**：`INSERT ... ON DUPLICATE KEY UPDATE` 找不到可冲突的唯一键 → **退化为纯 INSERT**，每请求插新行，回读永远 `count=1` → 限流失效 + 行数无限膨胀。
- **修复**：新增 `ensureUniqueCounterIndex()`——`SHOW INDEX` 探测 → 缺失则**先去重**（否则 `ADD UNIQUE` 在有重复行的库上必失败）→ 再 `ADD UNIQUE`，吞 1061 幂等，失败仅 `error_log` 不中断 API。

## 4. 遗留风险与后续建议

全部 37 项问题均已修复。仅剩 2 项**结构性技术债**（非缺陷）与若干流程改进建议。

### 结构性技术债

1. **`StorageInterface` 缺 LIST 能力** —— 本项目最贵的设计债：孤儿对象只能人工按 `{yyyy}/{mm}/{uuid}/` 前缀捞。本轮修的 A-06（queueClear 原子认领）只是止血。要根治需给接口加 `list(prefix)`，属架构级改动。
2. **`front.js` / `app.js` 的 API 测试器按行号切片同步** —— 注释已漂移（`'加载中…'` vs `'Loading...'`）。应改为按函数名提取，否则同类漂移必然复发。

### 流程改进建议

3. **配置层纳入 CI 门禁** —— 本次 P0 缺陷之所以能溜过 CI，正是因为三道门禁都不检查 `.htaccess` / `nginx.conf.example`。建议加轻量断言：`FilesMatch "\.php$"` 不得出现在 `src/.htaccess` 根、两个部署模板的拒绝清单必须一致。（本轮已在该文件留下 ⚠️ 注释，但注释不是防线。）
4. **API 行为变更需在发版说明中显著标注** —— A-19（category 404）、A-20（type 400）、A-14（列表过滤）都对既有调用方可见。虽属修正静默错误，但依赖旧宽松行为的调用方会受影响。
5. **测试基础设施入库** —— `p2_*.js` / `mr0*.js` / `audit_*.js` 只在 `.dsh/`（未纳入版本控制），CI 跑不到。建议按 HANDOFF 第 3.4 节迁入 `scripts/harness/`。
6. **死代码纳入定期清理** —— 本轮删除了 `ApiAuthMiddleware`、`CspNonce::htmlMeta/requireNonce`、`Config::save`、`Model::query/execute`。建议把「零引用检测」纳入例行检查，避免同类堆积。

### 已在本轮处理完毕（供追溯）

- A-12 限流 fail-open → fail-closed（503）
- A-13 预签名降级 → 降级前探测公开可读性
- A-26 / A-29 假配置 → `rate_window` 真正生效；`permissions` 在 UI 与模型层标注「当前不参与鉴权」
