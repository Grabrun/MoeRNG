# 全站文案规范

面向 `src/views/**`、`src/public/js/**`、后端 flash/错误信息、README 的文案基线。改文案前先读这一页。

## 1. 读者与场景

| 读者 | 场景 | 关心什么 |
|---|---|---|
| 开发者 | 首页 → 文档 → 在线测试 | 参数怎么传、失败长什么样、限额多少 |
| 站长 | 安装 → 后台 | 哪里配、按了会发生什么、出错怎么修 |
| 访客 | 图库 / 关于 | 这站是什么、图能不能拿走 |

同一句话只服务一类读者。给开发者看的参数说明里不夹「萌」字，给访客看的介绍里不出现 `process_status`。

## 2. 语气

- **具体 > 形容**：写「一次请求返回一张，`type=redirect` 直接 302 到图片」，不写「极致丝滑的取图体验」。
- **克制卖萌**：可以在空状态、成功提示里轻一点（「图库还是空的」），技术描述一律平实。
- **不承诺没测过的东西**：删掉「平均响应低于 50ms」这类无实测支撑的数字。
- **不加无信息标签**：`核心` / `推荐` / `NEW` 这类 badge，除非它能改变用户决策。

## 3. 语言

- 简体中文；专有名词保留英文原形：API、JSON、CDN、WebP、Token、CSP、FPM。
- 不造中英混词（不写「一键 deploy」「配置你的 storage」）。
- 数字与单位之间不加空格（320px、5 分钟、2.5 MB 除外——容量单位按习惯加空格）。
- 用中文引号「」，代码与参数名用反引号。

## 4. 术语表（全站统一，不再出现同义变体）

| 用 | 不用 |
|---|---|
| 随机图 / 随机图片 | 抽图、摇图 |
| 图库 | 相册、画廊 |
| 分类（含子分类） | 目录、标签 |
| 存储实例 | 存储桶、bucket 配置 |
| 处理队列 / 消费者 | 任务池、worker 进程（文档里可注明 worker） |
| 缩略图（sm / md / lg） | 小图、中图、大图 |
| 直链 | 外链、图片地址 |
| 站长 | 管理员用户、owner |
| 调用方 | 客户端、使用者 |

## 5. 禁止项（出现即改）

1. **与实现不符的描述**：`ORDER BY RAND()`（现为 COUNT + 随机 OFFSET）、「双语界面」（无此功能）、「对象存储前端直传」（已在 v1.3.1-beta.2 移除）。
2. **未实测的性能数字**：具体毫秒数、并发数、可用性百分比（首页可用性有真实统计来源，可保留）。
3. **营销腔**：一站式、极致、丝滑、赋能、重新定义、YYDS。
4. **重复说明**：同一段话在标题、副标题、说明里说三遍。
5. **空标记**：`-`、`暂无数据`、`TODO` 直接暴露给用户；空状态要说明「为什么空 + 下一步做什么」。

## 6. 结构约定

- 标题给结论，说明给条件，按钮给动作（「开始处理」而不是「提交」）。
- 错误信息三段：发生了什么 → 为什么 → 怎么办。例：
  `无法连接对象存储：AccessKey 无效。请到「存储管理」检查该实例的密钥。`
- 危险操作两段确认，第二段文案必须写明后果（删什么、能不能恢复）。
